# mtab 项目申报书

## 基本信息

- 项目名称：mtab（MoonBit 导航起始页）
- 参赛方向：新生态项目建设（Web 应用 / 示例工程）
- GitHub 仓库：https://github.com/2d5rrr333/mtab（36 个有效提交，全部在本赛期内，每个功能对应一个实质提交）
- 项目性质：原创；农历换算模块移植自 solarlunar 3.1.0（MIT，https://github.com/yize/solarlunar），修改点（干支年名跟随农历年）已在 README 与源码注明；节气采用寿星天文历公开公式

## 痛点与生态定位

MoonBit 前端缺一个"能跑起来用"的完整应用样板。mooncakes 上已有 2,391 个模块，lunar、pinyin、trie 各有库，但没有任何浏览器起始页或同类前端应用；想做 Web 项目的开发者只能找到库和小 demo，看不到"wasm-gc 和 DOM 到底怎么分工、状态放哪、事件怎么归约、测试怎么分层"的完整答案。

mtab 用一个真实可用的起始页回答这些问题：全部业务逻辑——状态机、事件归约、农历换算、检索评分、配置编解码——编译为 wasm-gc 承担，JS 壳仅约 1,000 行、只做重绘和副作用执行。这个"wasm 业务核心 + 薄 DOM 壳"架构（单一 store、`mtab_init`/`mtab_dispatch` JSON 桥、分区重绘）可直接复制到任何 MoonBit 前端项目。

与已有库的关系：mtab 零第三方依赖、不发布 lunar/pinyin/trie 库，不与库作者竞争；生态价值在应用与架构样板这一层，与库生态互补。

## 已有基础（赛期内已完成并验证）

时钟（公历/农历含闰月干支/24 节气天文历算/节日徽章）、书签分组与 Pointer Events 拖拽排序、多引擎搜索（trie 历史联想 + 频次×半衰期评分、~2000 字拼音表全拼/首字母联想）、深浅色主题令牌、壁纸与模糊度、config v1→v2 自动迁移、JSON 导入导出。质量基线：moon test 122、FFI 桥 e2e 46、Edge headless 双运行 214 项断言、GitHub Actions CI；OpenSpec 规格驱动开发，4 个 capability 31 条需求规格、10 个变更档案完整可追溯。

## 本次赛期新增（9/6 → 9/24，书签导入与倒数日小组件已交付）

1. **书签导入**（已完成）：Netscape 书签文件（Chrome/Firefox/Edge 导出的 HTML）解析器，纯 MoonBit 实现约 450 行——HTML 容错 tokenizer、`<DT><H3>` 分组与 `<DT><A>` 链接提取、实体转义还原，导入结果直接归约为现有分组事件，一键把浏览器书签搬进 mtab；
2. **倒数日小组件**（已完成）：自定义目标日（生日/考试/纪念日），显示剩余天数（还有 N 天 / 就是今天 / 已过 N 天），复用已有公历基础设施保证跨年/闰年正确，纳入现有小组件显隐配置，跨日自动刷新；
3. **工程收尾**（进行中）：发布 mooncakes.io、打 v0.4.0 release、README 数字修正。

明确不做：账号与云同步、浏览器扩展、移动端适配——数据全部本地 localStorage，离线可用，边界清晰。

## 实现路径

架构不变：单一 store 把每个事件归约为「新状态 + 副作用列表」，wasm 永远是唯一决策点，JS 壳零决策。书签导入在 model 层新增解析器（输入 HTML 字符串、输出分组书签结构，纯函数、独立可测），导入交互走既有 JSON 桥事件，不引入新 FFI 面；倒数日复用 widgets 配置与公历日期运算，不新增依赖。测试沿用三层：解析器以真实浏览器导出样例 + 嵌套文件夹/缺属性/非法行边界用例做单元测试；导入流程与组件交互走 e2e 与 headless 断言；全程 OpenSpec 规格先行，验收对照申报承诺。
