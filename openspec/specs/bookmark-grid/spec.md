# bookmark-grid

## Purpose

以图标网格形式分组展示与管理常用站点书签，作为导航页的核心导航入口；用户可增删改书签、组织分组并拖拽排序，点击直达站点。

## Requirements

### Requirement: 书签网格展示
页面必须以网格形式展示已保存的书签，每个书签显示其名称与图标；点击书签必须在新标签页打开其目标网址。

#### Scenario: 展示已保存书签
- **WHEN** 用户已保存至少一个书签并打开页面
- **THEN** 网格中显示该书签的名称与图标

#### Scenario: 点击打开站点
- **WHEN** 用户点击某个书签
- **THEN** 浏览器在新标签页打开该书签的目标网址

#### Scenario: 空状态
- **WHEN** 用户没有任何书签
- **THEN** 网格区域显示引导用户添加书签的提示与入口

### Requirement: 添加书签
用户必须能够通过名称与网址添加新书签，并可指定目标分组（缺省为默认分组）。输入的网址缺少协议时必须默认补全为 `https://` 后保存；空网址或格式无效的网址必须被拒绝并给出提示。

#### Scenario: 添加书签成功
- **WHEN** 用户填写名称"示例"与网址 `example.com` 并确认添加
- **THEN** 书签以网址 `https://example.com` 保存到所选分组（未选时为默认分组），并立即出现在该分组网格中

#### Scenario: 拒绝无效网址
- **WHEN** 用户填写空网址或格式无效的网址并确认添加
- **THEN** 系统提示网址无效，书签不被添加

#### Scenario: 添加到指定分组
- **WHEN** 用户在添加弹窗中选择分组"工作"并确认
- **THEN** 新书签出现在"工作"分组中

### Requirement: 编辑书签
用户必须能够修改已有书签的名称与网址；保存后网格必须立即反映修改。

#### Scenario: 修改书签
- **WHEN** 用户将某书签的名称与网址修改后保存
- **THEN** 网格中该书签显示新名称，点击时打开新网址

### Requirement: 删除书签
用户必须能够删除已有书签；删除后书签从网格移除且不再持久化。

#### Scenario: 删除书签
- **WHEN** 用户对某书签发起删除
- **THEN** 该书签从网格消失，刷新页面后也不再现

### Requirement: 图标回退
书签的站点图标获取失败时必须回退显示占位图标（如名称首字符），不得出现空白或破损图标。

#### Scenario: 图标获取失败
- **WHEN** 某书签的站点图标无法获取
- **THEN** 该书签显示占位图标

### Requirement: 分组管理
用户必须能够新建分组（名称必填且非空）、重命名分组、删除分组；删除分组时组内全部书签必须自动移回默认分组，不得丢失。默认分组不可删除、不可重命名。分组名称必须持久保存。

#### Scenario: 新建分组
- **WHEN** 用户输入名称"工作"并确认新建分组
- **THEN** 出现名为"工作"的空分组，刷新后仍存在

#### Scenario: 重命名分组
- **WHEN** 用户将某分组重命名为"学习"
- **THEN** 该分组标题立即更新并持久保存

#### Scenario: 删除分组书签回落
- **WHEN** 用户删除包含 2 个书签的非默认分组
- **THEN** 该分组消失，2 个书签出现在默认分组中且不丢失

#### Scenario: 默认分组不可删改
- **WHEN** 用户对默认分组发起删除或重命名
- **THEN** 操作被拒绝并提示，默认分组保持不变

### Requirement: 拖拽排序
用户必须能够通过拖拽调整书签顺序（组内换位）与移动书签到其他分组（跨组移动），以及拖拽分组标题调整分组顺序；拖拽过程中必须显示插入位置指示；操作在松开鼠标时生效并立即持久保存。拖拽不得与书签点击打开、编辑、删除操作冲突（短位移视为点击）。

#### Scenario: 组内换位
- **WHEN** 用户将某组内第 1 个书签拖拽到第 3 个位置松开
- **THEN** 该书签出现在第 3 位，顺序持久保存

#### Scenario: 跨组移动
- **WHEN** 用户将分组 A 的某书签拖拽到分组 B 的网格区域松开
- **THEN** 该书签移入分组 B 并持久保存

#### Scenario: 分组换序
- **WHEN** 用户将某分组标题拖拽到另一分组上方松开
- **THEN** 分组顺序调换并持久保存

#### Scenario: 点击与拖拽不冲突
- **WHEN** 用户在书签上按下并几乎未移动就松开
- **THEN** 不发生拖拽排序，按点击行为处理（打开站点或显示操作按钮）

### Requirement: 分组折叠记忆
用户必须能够折叠与展开任意分组（含默认分组）；折叠后该分组的书签网格隐藏、仅保留组头；折叠状态必须持久保存，刷新页面后保持。

#### Scenario: 折叠与展开
- **WHEN** 用户点击某分组的折叠按钮
- **THEN** 该分组网格立即隐藏，按钮指示切换为折叠态；再次点击恢复展开

#### Scenario: 折叠状态持久
- **WHEN** 用户折叠某分组后刷新页面
- **THEN** 该分组仍处于折叠状态

### Requirement: 初始推荐书签
首次使用（无本地存储配置）时，默认配置必须在默认分组预置一组常用站点书签，使导航页开箱即用；预置书签与用户自建书签行为一致（可编辑、删除、拖拽、导入去重）。已有本地配置的用户不受影响，不被覆盖或追加。

#### Scenario: 首次打开即有推荐书签
- **WHEN** 全新用户首次打开导航页（本地无配置）
- **THEN** 默认分组中显示预置的常用站点书签

#### Scenario: 预置书签可正常管理
- **WHEN** 用户对某条预置书签执行编辑或删除
- **THEN** 操作与自建书签一致，结果被持久保存

#### Scenario: 已有配置不被追加
- **WHEN** 用户已保存过配置（含或不含预置书签）后再次打开
- **THEN** 使用本地配置，不再注入预置书签

### Requirement: 书签文件导入
用户必须能够导入浏览器导出的 Netscape 书签文件（Chrome/Firefox/Edge 通用的 `<!DOCTYPE NETSCAPE-Bookmark-file>` HTML 格式）：系统解析其中的分组（`<H3>`）与书签（`<A>`），把有效分组与书签并入现有书签网格。导入必须保持文件夹嵌套中的有效条目不丢失，解析或导入完成后必须汇报结果（新增分组数与书签数）。

#### Scenario: 导入标准书签文件
- **WHEN** 用户导入包含分组"工作"（2 条书签）与默认层级书签（1 条）的标准 Netscape 书签文件
- **THEN** 出现"工作"分组且含 2 条书签，默认层级书签进入默认分组，汇报"新增 1 组 3 条"

#### Scenario: 解析容错
- **WHEN** 导入的文件存在属性无引号、标签大小写混用、多余空白、未知标签等常见偏差
- **THEN** 解析不失败，仍提取出全部有效分组与书签

#### Scenario: 实体转义还原
- **WHEN** 书签名称或分组名含 HTML 实体（如 `&amp;`、`&lt;`、数字实体）
- **THEN** 还原为对应字符后保存（`&`、`<` 等）

#### Scenario: 嵌套文件夹
- **WHEN** 书签文件中的分组存在嵌套（子文件夹）
- **THEN** 全部层级分组均被创建，深层书签归入对应深度的分组

#### Scenario: 无效行跳过
- **WHEN** 某条目缺少网址、网址无效或缺少名称
- **THEN** 该条目被跳过，其余有效条目正常导入

#### Scenario: 非法文件拒绝
- **WHEN** 导入内容不是有效的 Netscape 书签文件（如任意 HTML 或空文件）
- **THEN** 系统提示导入失败并说明原因，现有书签不受影响

### Requirement: 导入合并规则
导入必须与现有书签安全合并：导入分组与现有分组同名时，书签并入现有分组；任何与现有书签（或本文件内已导入书签）URL 相同的书签必须跳过，不得产生重复条目。导入后现有分组顺序与书签顺序保持在前，新分组追加在后。

#### Scenario: 同名分组合并
- **WHEN** 导入文件含分组"工作"，现有书签网格已有同名分组"工作"
- **THEN** 导入书签并入现有"工作"分组，不新建重复分组

#### Scenario: URL 去重
- **WHEN** 导入的书签 URL 与现有某书签相同（或与同批已导入书签相同）
- **THEN** 该书签被跳过并计入跳过数

#### Scenario: 现有顺序保持
- **WHEN** 导入完成后查看分组列表
- **THEN** 现有分组与书签的顺序不变，新分组与新增书签追加在各自末尾
